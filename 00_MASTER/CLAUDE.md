# 00_MASTER — Working instructions for Claude

This is the **brain** of the FortuneMarq build: strategy, system design, roadmap, brand, and the
machine-generated live snapshot. Everything else either feeds this or is governed by it.
Folder purpose/inventory lives in the `00_MASTER/*.md` docs below — this file is **how to work here**.

## Read first (source of truth, in order)
1. `LIVE_STATE.md` — machine-generated live snapshot (Supabase counts + deploy state). Authoritative for current data.
2. `FMOS_System_Design_And_Tasks.md` (newest dated entries) + `FMOS_Execution_Roadmap.md` — build state + order.
3. `MASTER_CONTEXT.md` — business identity, vision, positioning. `CRITICAL_PATH.md` / `PENDING_ACTIONS.md` — launch gate.
4. App handoff lives outside here: `01_CRM_AND_TOOL/fmos/CONTINUE_HERE.md`.

## How to work here
- **Never hand-edit `LIVE_STATE.md`.** It is regenerated by `scripts/doc_sync.mjs`. To refresh/reconcile docs, run the `/sync-docs` skill.
- When build facts change, update `FMOS_System_Design_And_Tasks.md` (dated progress entry) + the roadmap first — they are the build-state source of truth that other folders cite.
- This folder is **docs + assets only**. No app source, no data CSVs, no secrets.
- Keep edits truthful and dated. Convert relative dates ("yesterday") to absolute. Don't fabricate counts — pull them from `LIVE_STATE.md`.
- `Bot_Knowledge_Base/` is the bot's source of truth — edits there change what the AI bot (6.1) says. See its own CLAUDE.md.

## Boundaries
- Don't delete the `.docx`/`.pptx` strategy artifacts — they're owner-authored records.
- Don't push to `main` (auto-deploys). Work on the session branch; docs commits only unless told otherwise.
